# ROADSoS API Reference

The ROADSoS backend is built with FastAPI. It handles dynamic geospatial lookups, real-time WebSocket connections for live tracking, and employs rate limiting to prevent abuse.

Base URL: `http://localhost:8000` (Local) / `https://your-backend-url.com` (Production)

---

## 📡 REST Endpoints

### 1. Health Check
Checks if the backend is running and responsive.

*   **URL**: `/health`
*   **Method**: `GET`
*   **Response**: `200 OK`
```json
{
  "status": "healthy"
}
```

### 2. Create Tracking Session
Generates a unique session ID used to establish a WebSocket room for live location tracking.
*   **URL**: `/api/create-session`
*   **Method**: `POST`
*   **Rate Limit**: 5 requests per minute (per IP)
*   **Response**: `200 OK`
```json
{
  "session_id": "a1b2c3d4-e5f6-7890-1234-56789abcdef0"
}
```

### 3. Get Emergency Services
Fetches nearby emergency services (Hospitals, Police, Repair Shops) based on coordinates. Implements parallel fetching across multiple Overpass API mirrors and Redis caching.

*   **URL**: `/api/emergency-services`
*   **Method**: `GET`
*   **Rate Limit**: 10 requests per minute (per IP)
*   **Query Parameters**:
    *   `lat` (float, required): Latitude of the accident.
    *   `lon` (float, required): Longitude of the accident.
    *   `radius` (int, optional, default: 5000): Search radius in meters.
*   **Response**: `200 OK`
```json
{
  "services": [
    {
      "id": 123456789,
      "name": "City General Hospital",
      "category": "hospital",
      "type": "trauma_center",
      "phone": "+1234567890",
      "lat": 18.5204,
      "lon": 73.8567,
      "address": "Main Street, Pune",
      "is_recommended": true
    }
  ]
}
```
*   **Notes**: 
    *   Results are cached in Redis for 5 minutes based on rounded coordinates to prevent redundant downstream API calls.
    *   Hospitals tagged with "trauma" or "emergency" are automatically flagged as `is_recommended = true` and sorted to the top.

## 🔌 WebSocket Endpoints

### 1. Live Tracking Stream
Establishes a bi-directional connection for broadcasting and receiving real-time GPS updates.

*   **URL**: `/ws/track/{session_id}`
*   **Method**: `WebSocket`
*   **URL Parameters**:
    *   `session_id` (string, required): The UUID generated by `/api/create-session`.

#### Connection Flow:
1.  **Connect**: Client opens the WebSocket.
2.  **Initial Payload**: If previous coordinates exist in the Redis cache for this session, the server immediately pushes them to the new client.
3.  **Client Push**: The victim's phone sends its coordinates as a JSON string:
    ```json
    {"lat": 18.5204, "lon": 73.8567}
    ```
4.  **Server Broadcast**: The server updates the Redis cache (TTL: 1 hour) and uses Redis Pub/Sub to broadcast this JSON string to *all* clients connected to the same `session_id`.

#### Error Handling
If the WebSocket disconnects, the frontend will attempt to silently reconnect or fall back to static coordinates. Ensure your deployment environment (e.g., Nginx, Render) is configured to handle WebSocket upgrade headers.
